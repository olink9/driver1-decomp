# Driver 1 decomp

A matching decompilation of **Driver: You Are the Wheelman** (PlayStation, 1999, Reflections), aiming for a
**native PC port**.

*Matching* means C source that compiles back to the **byte-identical** original executable, using the
original compiler. Once the code is C, it can be rebuilt for other platforms. Driver 2 already got this
treatment from [REDRIVER2](https://github.com/OpenDriver2/REDRIVER2). This repo does it for the first game.

> **No game data is included.** You need your own copy of the game. The target is the US release, Rev 1:
> `SLUS_008.42`, sha1 `94b44a84de2f9fa2dcaf120db2e7b3d74bc70d3d`.

## Is anyone else doing Driver 1?

Not that we could find (October 2026). If you searched GitHub for a Driver 1 decomp or PC port, this is what's out there:

| Project | What it is |
|---|---|
| [OpenDriver2/REDRIVER2](https://github.com/OpenDriver2/REDRIVER2) | Driver 2, reverse-engineered to C and running natively on PC. Mature and playable. |
| [OpenDriver2/OpenDriverEngine](https://github.com/OpenDriver2/OpenDriverEngine) | An engine *inspired by* Driver 1 and 2: Driver 2 physics, with Driver 1 content recreated in Lua. Not a faithful Driver 1, and inactive since 2025. |
| [OpenDriver2/OpenDriver2Tools](https://github.com/OpenDriver2/OpenDriver2Tools), [TecFox](https://github.com/TecFox)'s extractors | Tools for Driver 1/2 data files: levels, music, sounds. |
| **This repo** | Driver 1's own code, function by function, byte-exact. |

those C files in place of the original code, and it must come out byte-identical (see *How a match is

**What these numbers cover:**
- The counts are for the game code in the main executable. The PsyQ (Sony SDK) library functions come after
  `__main` (0x738F0). They are identified from signatures but not decompiled, since the PC port replaces them.
- The overlays are not split yet: front end, memory card, credits, replay viewer, the `DT?.BIN` modules and the
  FMV player.
- **Near-misses** are complete C files that differ from the original only in small ways, almost always a
  different register choice by the compiler. They already behave like the original. They just aren't proven
  byte-exact yet.
- **Hand-written asm:** 56 routines (mostly GTE 3D-maths code with custom calling conventions, plus a decompressor)
  were written in assembly by Reflections. They are kept as assembly, marked `/* HANDWRITTEN ASM */`, and counted separately.
- **`FAKEMATCH`:** the bytes match, but only through a compiler hint (an empty `asm` statement, an alias name, a `volatile` cast, a
  `do { } while (0)` wrapper or a dead store)
  that the original source almost certainly didn't use. These files are marked and wait for a better C form.

### Roadmap
1. Match the remaining functions in the main executable.
2. Split and match the overlays.
3. Merge the per-function files in `src/pilot/` into real source files with shared types, and apply the
   collected names (`pilot/names-proposed.tsv`; many come from Driver 2's debug symbols).
4. Port to PC on [PsyCross](https://github.com/OpenDriver2/PsyCross), the compatibility layer REDRIVER2 uses.

## How a match is verified

There are two independent checks, and nothing counts on an agent's (or a person's) word.

1. **`tools/fnscore.py`** compiles one C file through the original toolchain and diffs the function with
   [objdiff](https://github.com/encounter/objdiff) against the original function. `MATCH 100.0` means zero
   differing instructions. The score is never rounded up.
2. **`tools/linkcheck.py`** links every matched C file into the real build, in place of the original code,
   and compares the resulting executable byte for byte with the original. All relocations resolve through
   the linker; nothing is patched by hand. It also links all passing functions together and checks the
   sha1 of the full executable.

The link check has already caught real problems the per-function scorer missed: two false matches (a
register difference on a relocated instruction) and two hand-written routines that were 4 bytes too long.
All of them were fixed or demoted.

**Toolchain (confirmed):** GCC 2.7.2 (`cdk` build from [decompals/old-gcc](https://github.com/decompals/old-gcc)),
`-O2 -G8`, then [maspsx](https://github.com/mkst/maspsx) emulating aspsx 2.79, with a small patch
(`tools/maspsx-extern-gp.patch`: small externs ≤ 4 bytes are gp-relative, 8-byte ones absolute).
Thirteen compiler builds were tried; only this one matched everything.

## About AI

**This decompilation is being done by AI agents.** Claude models (Anthropic) write the C, run the tools
and iterate. [@olink9](https://github.com/olink9) directs the work and owns the project. Most of the
matching so far was done in a single day by agents working in parallel. Every agent reads
`pilot/AGENT.md`, which collects the compiler patterns they discovered along the way.

What that means for you:
- **The bytes don't care who wrote the C.** A match is checked by the compiler and the link check above,
  not by trusting the author. A function either rebuilds the original executable exactly or it doesn't count.
- **The C is not "the original source".** Like any matching decomp, it is *a* source that compiles to the
  same code. Names, types and structure are best guesses, informed by Driver 2's debug symbols where the two
  games share code.
- **Readability is not there yet.** Per-function files, placeholder names (`func_0004E9C4`, `D_00097530`)
  and local struct definitions are expected at this stage. Cleanup into real source files is on the roadmap.
- If you prefer not to use or contribute to AI-assisted projects, that's completely fine. The tools and
  findings here (compiler identification, the maspsx patch, the Driver 2 symbol mapping) may still be useful
  for your own work.

## Building

You need Linux (or WSL/distrobox), Python 3, and your own copy of the game.

```sh
tools/setup.sh                                  # MIPS binutils, splat, maspsx (+patch), old GCCs
# copy SLUS_008.42 from your disc to orig/SLUS_008.42, then:
.venv/bin/python -m splat split fn.yaml         # one asm file per function (scoring targets)
.venv/bin/python -m splat split slus_008.42.yaml
make                                            # rebuilds a byte-identical SLUS_008.42
```

Scoring one function, and the link check:
```sh
.venv/bin/python tools/fnasm.py func_0004E9C4                         # target asm + Driver 2 hints
.venv/bin/python tools/fnscore.py func_0004E9C4 src/pilot/func_0004E9C4.c --diff
.venv/bin/python tools/linkcheck.py -o pilot/linkcheck.tsv            # all matched files
.venv/bin/python tools/progress.py                                    # the table above
```

`objdiff-cli` is expected at `~/.local/opt/decomp/objdiff-cli`; set `OBJDIFF` to override. The Driver 2
hints in `fnasm.py` need two optional checkouts, each with its own environment variable:
- `REDRIVER2_GAME`: the `src_rebuild/Game` directory of OpenDriver2/REDRIVER2.
- `D2_SYMBOL_DUMP`: `symbols/spanish_dump.h` from the archived SoapyMan/REDRIVER2 repo.

## Layout

| Path | |
|---|---|
| `src/pilot/*.c` | matched functions, one file each; `.wip.c` = best attempt so far |
| `include/` | PsyQ types and macros (PsyCross headers, configured for real PSX layouts), `gte.h` |
| `slus_008.42.yaml`, `fn.yaml` | splat configs: baseline build, and one asm file per function |
| `symbol_addrs.txt` | named symbols (PsyQ library, confirmed names) |
| `pilot/AGENT.md` | the matching guide: toolchain, rules, ~80 compiler patterns learned so far |
| `pilot/queue.tsv` | all 799 game functions, smallest first |
| `pilot/results.tsv`, `pilot/linkcheck.tsv` | every attempt, and the link-check verdicts |
| `pilot/d2map.tsv` | Driver 1 ↔ Driver 2 function pairs (code similarity) |
| `pilot/names-proposed.tsv` | names found so far, not yet applied |
| `pilot/retry-notes.md` | open problems and leads |
| `tools/` | scorer, link check, disassembly helper, Driver 2 matcher, PsyQ signature matcher |

## Contributing

Issues and pull requests are welcome, from people and from people's agents. A PR that adds or changes a
match must pass `tools/linkcheck.py`. Please don't commit anything taken from the game disc. This repo
contains no game data, and `.gitignore` keeps `orig/`, `asm/` and `build/` out.
